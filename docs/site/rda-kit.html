The format

Every episode runs the same five phases

The order never changes. The result is always shown before the debrief starts. Phase B4 is the longest stretch and the biggest drop-off risk, so it is split into three timed sections with the strongest material first.

B1
B2
B3
B4 · synthesis
B5
0:00 2:00 5:00 8:00 ~10:00
B1Hook and constraints. Name the exam, the clock, and your honest baseline.
B2Stakes. The pass line as an exact number, the reward, the punishment prop.
B3Test and result. Timer montage, the score straight from the scorer, the payoff.
B4Synthesis: counterintuitive concepts, cross-domain patterns, core knowledge. About two minutes each.
B5Disclosed sponsor read and the next-episode seed. Hatched because its end is open.
The journey

From idea to published, and where the tool helps

This is the order things usually happen in. You will not always follow it, and you don't need to: rda status reads what is on disk and tells either of us the next step from wherever you are.

the tool does this step you do it, the tool tracks it
  1. Plan
  2. Park the ideaNo ceremony. It lands in docs/ideas.md with the date.
    rda idea "…"
  3. Start an episodeCopies the template into episodes/001-slug/ and starts its log.
    rda new <slug>
  4. Fill the exam cardExam, source, rights check, time limit, pass line, stakes, sponsor.
    exam-card.md
  5. Start
  6. Build exam.jsonQuestions plus the official key. I can build this from a PDF and its key so you never see the answers.
    exam.json
  7. Freeze itValidates, hashes, seals the key, writes your question sheet. Commit before studying.
    rda exam freeze
  8. Record B1 and B2Before studying, so the baseline and stakes are true when you say them.
    camera
  9. Record
  10. Run the clockA live countdown for the screen capture, with real start and stop times saved.
    rda clock start 360
  11. Score itPrints the on-camera score block and a per-topic tally.
    rda score
  12. Film the payoffOnly the outcome that actually happened.
    b-roll
  13. Produce
  14. Debrief and scriptBuilt from what the exam actually tested, in the format your Notion sync reads.
    debrief.md, script.md
  15. Hand offCreates videos/rda-001/ in claude-youtube-editor and exports the numbers for on-screen cards.
    rda handoff ../claude-youtube-editor
  16. Publish
  17. Your existing pipeline/clean-cut, /make-tsx, /suggest-sfx, /packaging, then yt_upload.py. Flip the paid-promotion toggle by hand if sponsored.
    pipeline repo

How the honesty works

One exam file in, three files out

The series promises viewers the exam was fixed before you studied and the score is real. Freezing is what backs that promise. It is an honor system, since the key lives in the same repo, but the committed fingerprint means any change after the fact is visible.

exam.jsonQuestions, options, and the official answers. Built before studying.you never open
exam freeze →
questions.mdQuestions and options only. Your test sheet.you read this
key.jsonThe answers, used only by rda score.sealed
FROZEN.jsonThe SHA-256 fingerprint and time. Also written into the exam card.commit and show

What the critiques changed

You asked for three rounds of self-critique. Each one changed the work.

1

Round 1: documents, not a tool

The first commit was all docs and templates. Nothing ran, and the honesty rules depended on things no code did. That led to building rda.py.

2

Round 2: too much, and missing the important part

I cut a terminal test runner and pipeline plumbing for a video that does not exist yet. I added what working together needs: idea for random ideas, status for picking up anywhere, a log, and a CLAUDE.md so any future session of mine knows the formula.

3

Round 3: a real dry run found three bugs

You could not take the test without seeing the answers, because there was no question-only sheet. Real exams were forced to carry an explanation per question, which would have meant inventing them. And --episode only worked in one position. All three are fixed.

✓

Proved, not assumed

For each fix, I put the bug back on purpose and confirmed a test catches it. All five planted defects were caught. The tests also check that the tool refuses bad input: a tampered exam, a second freeze, a bad answer letter, a leaked answer on the question sheet.

The promise to viewers

The viewer contract

Nine rules every episode keeps. Breaking one costs more trust than one video earns.

  1. 1The clock is real and visible.
  2. 2The pass line is stated before the test and never moved.
  3. 3The exam is frozen before studying starts.
  4. 4The baseline is stated honestly.
  5. 5The score comes from the scorer, not retyped.
  6. 6The debrief is labeled a first-timer's take, not advice.
  7. 7AI-generated exams are labeled as such.
  8. 8Sponsors are disclosed out loud and in YouTube settings.
  9. 9The payoff is real. Nothing is staged to match a script.
Still open

What is not built, and why

Your exam pick

If episode 001 uses an online test that grades itself, we never get the key, so rda score can't help. Recording the vendor's score is a small addition. I'll build it once you pick, if needed.

AI exam generation

The protocol is written: generate from the official outline, require a source per question, check the answers blind three times. It needs an API key and its own design pass. Episode 001 uses a real exam.

On-screen cards

Timer, pass line, score, and tally cards for Remotion. They will read episode.json. Built in the editor repo when there is footage.

Four options only

Questions are A to D. If your exam has five options, tell me and I'll widen it.
