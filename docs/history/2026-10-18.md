# 2026-10-18: a strategy brief for the series

A cloud session that reviewed all of the owner's project repos and wrote one strategy page per
project, so each project can stand on its own and serve a specific market. RDA's page is
`docs/STRATEGY.md`, linked from the top of the README.

## What we did

- Researched RDA's market: viewer segments, comparable channels, sponsor and affiliate benchmarks,
  and how fast new channels grow. The research read this repo without changing it and searched the web.
- Wrote the brief: positioning, segments with a beachhead (people weighing a real exam), a pricing
  ladder built on affiliates and sponsors, a 90-day plan, KPIs, risks, untangling steps and the open
  decisions.
- Published it here as `docs/STRATEGY.md`, generated from the same data as the full page.

## Why

The owner asked for each project to be untangled from the others. RDA has no channel yet, which makes
now the cheapest moment to give it its own channel, tracker and topic rubric.

## What we found

- Episode choice should follow exam search demand; the FCC Technician exam in PR #3 fits.
- RDA's status and topics lean on other projects today; the brief's Untangling section lists each tie.

## What we got wrong

- The first pass kept every strategy page in the owner's private `_workbench` repo only. The owner
  wanted each project's page on its own repo, so this copy was added the same day.
- This repo is public, so `docs/STRATEGY.md` is the public edition. The full brief lives in the owner's
  private `_workbench` repo, in `portfolio-strategy/`.

## Later the same day

A review of missed opportunities added one rule to the brief's untangling steps: choose episodes by the
rubric, but when a credential also pays (an FAA Part 107 certificate makes paid drone work legal), say
so on camera as part of the stakes.
