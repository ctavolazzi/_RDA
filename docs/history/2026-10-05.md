# 2026-10-05: from a pasted concept to a home base

The first working session on RDA. One long conversation between the user (ctavolazzi) and Claude
Code, in a cloud container with the user's GitHub repos checked out side by side. This entry is the
record future sessions should read to understand how the repo got its shape. Decisions are in
`docs/decisions.md`; this is the story.

## Where we started

The user pasted a project concept for the RDA Challenge series (five-phase format, pass/fail stakes,
real or AI-generated exams, a technical debrief, sponsor and next-episode seed) with no explicit ask.
`ctavolazzi/_RDA` was an empty repo with a one-line README, and every repo in the session had a branch
named `claude/rda-challenge-series-eo8iyc`. Claude took `_RDA` as the home for the series.

Context about the user that shaped the work: they are building a YouTube channel from the ground up,
they run Johnny Autoseed LLC (supply chains for the autonomous era, starting with FarmBot), they do not
want em dashes anywhere, and they do not want PRs watched.

## What happened, in order

### 1. Foundation docs (commit `0708bbd`, PR ctavolazzi/_RDA#1)

Turned the concept into `docs/format.md` (the arc plus a nine-rule viewer contract), `docs/exam-sourcing.md`
(real exams first; AI-generated only with a blueprint, citations, blind multi-run key verification, a
human spot-check, and a frozen hash), `docs/production.md`, `docs/risks.md` (the concept's three risks
plus seven), `docs/backlog.md`, `schemas/exam.schema.json`, and `episodes/_template/`.

### 2. Scan of the other twelve repos

Four read-only subagents scanned the user's other repos for anything useful. Most valuable: the
`claude-youtube-editor` pipeline (Remotion + Python, a fork of Hasan Aboul Hasan's MIT project), the
`_pyrite` operating prompt ("never report a green check you have not watched go red"), the `_workbench`
dated "nothing estimated" work log, and `commentary-studio`'s license-aware media fetcher. Not useful:
AI-Vtuber (retired GPT-3 API chat bot), fogsift-icarus (a stub), stock FastAPI, awesome-design-patterns
(a link list). RedditVideoMakerBot is GPL-3.0, so ideas only. Nothing anywhere did exam generation.

### 3. Three rounds of self-critique, at the user's request

- **Round 1:** the foundation was documents, not a tool. Nothing ran, and the viewer contract depended
  on things no code did. Designed `tools/rda.py`.
- **Round 2:** that design was too much in places (a terminal test runner, generated pipeline plumbing)
  and missed what working together needs (a verb for random ideas, a status command that works out of
  order, a log, a CLAUDE.md). Built the tool with nine verbs and a test file (commit `38ddcf6`).
- **Round 3:** a full end-to-end dry run in scratch found three real defects: no question-only sheet
  (the host could not take the test without seeing the key), real exams forced to carry a per-item
  rationale (which would have meant inventing them), and `--episode` only working before the verb. All
  fixed (commit `38369f3`), and each fix was proven by planting the bug back and watching a test catch it.

### 4. The RDA Episode Kit page

A standalone HTML explainer of everything built, published as a private artifact:
https://claude.ai/artifact/Gc6Rs1qn8BPs8vcSr4A8xb . Source kept at `docs/site/rda-kit.html`. It is a
snapshot from before the consolidation below, so it still describes two repos.

### 5. The animated explainer video (commits `962769e`, `c0049ca` in claude-youtube-editor, PR #3 there)

A 60s, 1080p30 Remotion explainer, seven scenes, text-led with a music bed and SFX, in the same
exam-booklet look as the page. Details and lessons: `docs/explainer-video.md`.

### 6. Consolidation into `_RDA` (this commit)

The user asked for one home base. The pipeline was vendored in from `claude-youtube-editor` at commit
`c0049ca` (provenance and local changes: `docs/vendored.md`), `rda handoff` now targets this repo by
default, the explainer and its fonts moved in, and the render and mastering steps became tools
(`remotion/scripts/render-one.mjs`, `tools/master_audio.py`). The explainer was then re-rendered and
re-mastered from `_RDA` alone to prove it works.

## What we discovered

- **The format's credibility rests on the exam freeze.** The hash, the sealed key and the question sheet
  are the mechanism behind "the test is real". It is an honor system (the key is in the same repo), which
  is fine for a YouTube challenge if said on camera.
- **A dry run beats a re-read.** The three defects in round 3 were invisible on paper and obvious the
  moment the tool was used the way the user will use it.
- **The environment shapes the pipeline.** In the cloud container there was no ElevenLabs key (so no
  voiceover), headless Chrome rejected the proxy certificate (so Google Fonts failed at render time),
  and Remotion's default 30s `delayRender` timeout expired in parallel render tabs. On the user's own
  Windows machine the first two do not apply.
- **Loudness needs measuring, not guessing.** The first export was -32 LUFS. YouTube never turns quiet
  videos up.
- **`yt_upload.py` had a latent path bug** in a standalone checkout: it resolved plan paths against the
  directory above the repo (a monorepo leftover). Fixed in the vendored copy.

## What we got wrong (and when it might turn out right)

Kept here on purpose. Several of these were right for their moment and could be right again.

| What | Why it was wrong today | When it might be right |
|---|---|---|
| Docs before any tool | Nothing enforced the contract the docs described | If collaborators join, docs-first onboarding helps |
| Two repos, handoff between them | Spread the work out; the user wants one home base | If the upstream pipeline moves fast and we want its updates automatically |
| Proposing `_pyrite`'s ticket system | Too heavy for one person making episode 001 | A team, or many episodes in flight at once |
| A terminal test runner (`exam take`) | Real exams come as PDFs or vendor portals | AI-generated exams with no other way to take them |
| Handoff generating `timeline.json` and `publish.json` | Plumbing for a cut that did not exist yet | After episode 001 shows which parts repeat |
| Requiring rationale and citation on real exams | Pushed toward inventing them | Still required for AI-generated exams |
| Relaying subagent scan results with partial checks | Some claims were garbled; verify before relaying | Never; always verify |
| Mixing the explainer's music as if a voice sat on top | -32 LUFS export | When narration is added, lower the bed again |
| Piping a render into `grep`/`tail` | A failed render was reported as success | Never; log to a file and check `$?` |
| Text-only explainer | A constraint (no voice key), not a choice | Narration would likely be stronger; see open items |

## Open items

1. **Pick episode 001's exam.** If it is an online test that grades itself, add an "external scorer" mode
   to `rda score` (record the vendor's score, no key on our side).
2. **Adopt the RDA look as the brand.** Run `/brand-setup` with the palette and fonts from
   `remotion/src/shots/rda-explainer/_kit.tsx`; the brand files still hold the upstream indigo style.
3. **Narration for the explainer.** Add `ELEVENLABS_API_KEY` and use `tools/gen_vo.mjs`, or record it and
   retime the scenes.
4. **LLM exam generation with blind verification.** Protocol in `docs/exam-sourcing.md`. Needs an API key
   and its own design pass.
5. **Episode cards** (timer, pass line, score, tally) that read `videos/rda-NNN/work/episode.json`. The
   explainer's `_kit.tsx` (Stamp, Bubble, Terminal) is a starting point.
6. **PR housekeeping:** ctavolazzi/_RDA#1 carries all of this. ctavolazzi/claude-youtube-editor#3 is now
   redundant (its contents live here); the user decides whether to close it.
7. **Unknowns:** the Notion tracker's Stage options (`notion.json` guesses `Scripting`, and `notion_sync.py`
   fails safely on a wrong value); exams with more than four options.
